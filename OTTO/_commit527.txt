5.27: Exit/trailing milestones + custom order comment identifier

EXIT & TRAILING (COttoTradeManager.mqh, OttoDefines.mqh)

Breakeven now fires at 1:1. InpBreakEvenRR lowered 2.0 -> 1.0 and the stop
moves to COST-COVERING breakeven (primaryEntry +/- beOffset), so a trip
there returns the account to flat rather than to a nominal loss. beOffset
still comes from CalcBasketFriction(), which sums commission, swap and
half-spread.

New step profit lock. InpLockProfitRR (3.0) ratchets the hard floor to
InpLockProfitTargetRR (2.0R). The milestone ladder is spaced exactly 1R
apart -- breakeven 1.0R, lock target 2.0R, lock trigger 3.0R -- which is
deliberate: a lock target at or below cost-covering breakeven would only
ever LOOSEN the stop, and ApplyUnifiedSL()'s ratchet would silently refuse
it. The lock is guarded strictly forward on both branches, so it can never
pull a stop backwards, and either input set to 0 disables it entirely.

The dynamic ATR trail is retained unconditionally past InpLock3RRR and is
now evaluated AFTER the step lock, so the tighter of the two wins on the
same tick: a near-market ATR trail supersedes the +2.0R floor, while the
floor holds in wide-ATR chop.

Tranche 2 decoupled from breakeven. It previously read InpBreakEvenRR,
which worked only because both inputs happened to equal 2.0; lowering
breakeven to 1.0 would have dragged the T2 scale-in down a full R early.
T2 now has its own InpPyramidT2RR (2.0), preserving historic behaviour.

SyncTradeState() classifies STEP_TRAILING off InpLockProfitRR, and the
stale ENUM_TRAIL_STEP comments naming fixed R:R values are corrected.

ORDER COMMENT IDENTIFIER (COttoOrderManager.mqh)

Comments no longer send the static TradeComment. New ClampOrderComment()
+ BuildOrderComment() helpers emit the journal session ID, falling back
to OTTO_<sym>_<serial> when no journal exists, and clamp to MT5's hard
31-char limit. All three sites route through them: the plain market path,
PlaceLimitOrder, and AddPyramidTranche (which appends _T<n>).

The clamp does NOT blindly take the first 31 chars. A raw session ID is
33-36 chars, so head truncation would chop off the -BLK<n> tail -- the one
field identifying the setup. Instead the YYYYMMDD- date component is
dropped first (validated as a digit-leading >=8-char segment so an
unexpected layout is never mangled), and only then is a middle-eliding,
tail-preserving clamp applied: head(25) + '~' + tail(5).

Modify/close/delete requests keep their _CLOSE/_MODSL/_DEL/_REV operation
tags -- those are operational markers, not setup identifiers.
