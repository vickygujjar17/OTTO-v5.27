570: fix — make the High Table aggregate-risk ceiling config-proof

RATIONALE

  v5.63 added an aggregate leg to AuditRiskExposure: it sums the loss-side
  percentage of every leg behind the shared stop and compares that sum against
  the stacked design budget, so a pyramid that is correctly sized leg-by-leg but
  over budget in total is still visible. That leg has one defect, and it is a
  false-CRITICAL defect of exactly the kind v5.46 removed the MathAbs form to
  avoid.

  1. THE CEILING WAS NOT PROOF AGAINST ITS OWN INPUTS.

     The budget was

         double nominalStackPct    = RiskPercent + InpRiskT2Pct
                                   + InpRiskT3Pct + InpRiskT4Pct;
         double maxAllowedStackPct = nominalStackPct * 1.50;

     The sum is only an upper bound while the tranche inputs are non-negative.
     InpRiskT2Pct, InpRiskT3Pct and InpRiskT4Pct are operator inputs and are not
     validated anywhere as a ladder: a zeroed, negative, or mis-typed set drives
     the sum BELOW RiskPercent, and the ceiling then resolves UNDER the primary
     rung. A plain single-leg basket trading at its own nominal risk reads above
     that ceiling and trips the aggregate leg -- firing a WARN on the most
     ordinary state the EA has, before any scale-in has ever happened. The check
     meant to catch over-pyramiding would instead punish correct flat sizing.

     The shipped defaults are 1.0 / 1.0 / 0.5 / 0.25, i.e. 2.75% nominal and
     4.125% with the 50% tolerance, and they are safe. The bug is latent, not
     active: it needs a bad config. Latent is not acceptable in a ceiling whose
     entire job is to be an upper bound -- a guard that can be made to under-read
     by the values it is guarding is not a guard.

  2. THE SUM IS DELIBERATELY RETAINED.

     The obvious "fix" is to drop the sum and test against RiskPercent alone, or
     to test each rung against its own budget. Both were rejected. The sum IS the
     pyramid's design ceiling -- 2.75% nominal, 4.125% with tolerance -- and a
     correctly-sized full ladder sits exactly at it, so it never alerts. Dropping
     it to a single-rung ceiling would alert WARN on every correctly-sized T1+T2
     basket, converting a targeted detector into constant noise. The defect is
     not that the sum is wrong; it is that the sum had no floor.

     The fix floors it at the primary rung:

         double maxAllowedStackPct = MathMax(nominalStackPct, RiskPercent) * 1.50;

     Under every sane config nominalStackPct >= RiskPercent, so the floor is
     INERT and the shipped ceiling is unchanged at 4.125% -- byte-for-byte the
     same number v5.63 produced. It only binds when the ladder has been driven
     below the primary rung, and it binds to the one value a single-leg basket
     cannot exceed. This is a hardening, not a trade-character change: no entry,
     no exit, no sizing and no position count moves.

  3. MathMax TAKES TWO ARGUMENTS.

     The release sketch spelled the bound with a four-argument MathMax. MQL5
     declares `double MathMax(double value1, double value2);`, so that form does
     not compile, and all 17 pre-existing call sites in this tree pass two args.
     The two-operand floor above is the compiling equivalent, and the arity is
     now stated in the doc box at the anchor so the mistake is not repeated.

  4. SCOPE.

     The other three items from the sketch were verified ALREADY SHIPPED in
     52d1c38 and are untouched here:

       * the deep front-edge entry geometry (near edge -/+ 2.0*H +/- 1.5*ATR),
         pinned by test_v557_frontrun.py:723/724;
       * the decoupled break veto anchored on the physical far edge,
         COttoBlockManager.mqh:731-734;
       * the journal actionDesc strings, pinned at the same probe lines.

     The journal strings were left verbatim. "SL 1R above/below entry" is
     factually correct -- CalcSLDistance is blockHeight + 0.5*atr, which is 1R by
     construction -- and dropping the "1R" would orphan the pin and make a true
     statement vaguer. No blueprint file exists in the tree; the sketch was the
     only source, and it was not a wording change.

     So v5.70 is a small hardening release carrying one line of shipped logic.
